Predictive Values and Prevalence

The same test result means different things in different places

1 Reading across the rows

In this chapter

  • Calculate positive and negative predictive value
  • Show how both change with prevalence while sensitivity and specificity do not
  • Apply Bayes’ theorem using likelihood ratios
  • Explain why a good test can still produce mostly false alarms

Chapter 2 read the table down its columns. Predictive values read it across the rows — starting from the result the patient actually has.

\[ \text{PPV} = \frac{TP}{TP + FP} \qquad\qquad \text{NPV} = \frac{TN}{TN + FN} \]

ppv <- tab$tp / (tab$tp + tab$fp)
npv <- tab$tn / (tab$tn + tab$fn)

c(ppv = round(ppv, 3), npv = round(npv, 3))
  ppv   npv 
0.333 0.992

In our cohort, a positive troponin carries a 33.3% probability of a confirmed infarction, and a negative one leaves a 0.8% residual probability.

2 The prevalence trap

Here is the result that surprises people. Hold the test constant — same assay, same threshold, same sensitivity of 96.1% and specificity of 71.7% — and vary only how common the disease is.

Applied as a population screen, this same test produces roughly 147 false alarms for every genuine case found. Nothing about the assay has deteriorated. The test is fine; the deployment is wrong.

The clinical consequence

This is the argument against unfocused testing. Ordering a troponin on a patient with a very low pre-test probability does not produce information — it produces a result that is more likely to be wrong than right, along with the admission, the anticoagulation and the angiogram that follow from it.

3 Work it out yourself

Move the sliders. Sensitivity and specificity start at the values from our cohort. The numbers recompute in your browser as you drag.

viewof prevalence = Inputs.range([0.001, 0.6], {
  value: 0.13, step: 0.001, label: "Prevalence (pre-test probability)"

viewof sensitivity = Inputs.range([0.5, 1], {
  value: sens_in, step: 0.005, label: "Sensitivity"
})
viewof specificity = Inputs.range([0.5, 1], {
  value: spec_in, step: 0.005, label: "Specificity"
})
cohortSize = 10000
diseased = cohortSize * prevalence
tp = diseased * sensitivity
fn = diseased - tp
tn = (cohortSize - diseased) * specificity
fp = (cohortSize - diseased) - tn
ppv_live = tp / (tp + fp)
npv_live = tn / (tn + fn)
lrPos = sensitivity / (1 - specificity)
lrNeg = (1 - sensitivity) / specificity
fmt = (x) => (100 * x).toFixed(1) + "%"
n = (x) => Math.round(x).toLocaleString("en")

Drag prevalence down towards 1% while leaving the test untouched, and watch PPV fall away. That single behaviour explains most of the controversy around population screening programmes.

4 Likelihood ratios: the portable version

Predictive values are specific to the population they were measured in, which makes them awkward to carry between settings. Likelihood ratios solve this. They describe the test, like sensitivity and specificity, but combine directly with any pre-test probability (Deeks and Altman 2004).

\[ LR^+ = \frac{\text{Sensitivity}}{1 - \text{Specificity}} \qquad\qquad LR^- = \frac{1 - \text{Sensitivity}}{\text{Specificity}} \]

lr_pos <- sn / (1 - sp)
lr_neg <- (1 - sn) / sp
c(LR_positive = round(lr_pos, 2), LR_negative = round(lr_neg, 3))
LR_positive LR_negative 
      3.400       0.054

Apply them in odds, then convert back:

\[ \text{post-test odds} = \text{pre-test odds} \times LR \]

1pre  <- 0.13
2odds_pre  <- pre / (1 - pre)
3odds_post <- odds_pre * lr_pos
4post <- odds_post / (1 + odds_post)

round(c(pre_test = pre, post_test = post), 3)

5 Check yourself

A test with sensitivity 0.99 and specificity 0.99 is used to screen for a condition affecting 1 in 10,000 people. A patient tests positive. Roughly what is the probability they have the condition?

In 1,000,000 people: 100 have the condition and 99 test positive. Of the 999,900 without it, about 9,999 test positive. So 99 out of roughly 10,098 positives are genuine — about 1%. An excellent test, applied to a rare condition, still yields a hundred false alarms per true case. Set the slider above to 0.0001 and watch it happen.

A patient’s pre-test probability is 20%. A test with a positive likelihood ratio of 8 comes back positive. The post-test probability is closest to:

Pre-test odds = 0.2/0.8 = 0.25. Post-test odds = 0.25 × 8 = 2. Probability = 2/(1+2) = 0.67. Note that you cannot simply multiply the probability by the likelihood ratio — 20% × 8 would give 160%, which is why the conversion to odds is not optional.
